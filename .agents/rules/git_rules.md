# Git 작업 및 보안 거버넌스 규칙 (Git Workflow & Security Rules)

## 1. 🛑 커밋 및 푸시 승인 원칙 (Strict User Authorization)
- **자동 커밋/푸시 금지**: 사용자의 명시적인 요청이나 지시가 없는 경우, 에이전트는 **절대로 임의로 `git commit` 또는 `git push`를 실행하지 않는다.**
- **명시적 요청 시에만 실행**: 오직 사용자가 "커밋해줘", "깃허브에 올려줘", "git push 진행해줘" 등 명시적으로 지시한 경우에만 git 작업을 수행한다.
- 작업을 완료했더라도 git 반영 여부는 사용자에게 질문하거나 확인을 요청하는 형태로 마친다.

---

## 2. 🔐 사전 민감정보 점검 의무 (Mandatory Pre-Commit Security Audit)
커밋 및 푸시 요청을 받았을 때, 에이전트는 `git add` 및 `git commit`을 실행하기 전 **반드시 아래 체크리스트를 검증**해야 한다:

1. **`git status` 확인**:
   - 커밋 대상 파일 목록을 전수 검토한다.
2. **민감정보 및 보안 파일 포함 여부 전수 차단**:
   - ❌ 구글 서비스 계정 키 및 인증서: `config/auth/*.json`, `credentials.json`, `*.pem`, `*.key`
   - ❌ 환경 변수 및 시크릿: `config/.env`, `.env`, `.env.*` (`.env.example` 제외)
   - ❌ 가상환경 및 바이너리: `.venv/`, `venv/`, `__pycache__/`, `*.pyc`
   - ❌ 개인 메모: `todo.txt`, `todo2.txt`, `notes/`
3. **만약 민감 파일이 추적(Tracked) 상태라면**:
   - 커밋을 즉각 중단(Fail-safe)하고, 사용자에게 알린 후 `git rm --cached` 및 `.gitignore`를 점검한다.

## 3. 🏷️ 버전 기반 커밋 메시지 컨벤션 (Semantic Patch Tracking)
커밋 메시지는 반드시 대상 프로덕트 버전 태그(`[MAJOR.MINOR.PATCH]`)를 선두에 기재하고, 작업 사유 또는 표준 대체문구를 명시한다:

1. **메시지 기본 포맷**:
   - `[MAJOR.MINOR.PATCH] 작업 사유` (명확한 신규 기능/작업 사유가 있는 경우)
   - `[MAJOR.MINOR.PATCH] 대체문구: 상세 내용` (단순 수정/유지보수인 경우)
   - 예시:
     - `[1.0.1] 총기 정보 도감 및 3단계 교차검증 파이프라인 구축`
     - `[1.0.2] 코드개선: URL Hash 라우터 및 실시간 캐시 버스팅 적용`
     - `[1.0.3] 버그수정: 보급 무기 열 밀림 및 다리 데미지 오류 해결`
     - `[1.0.4] 문서수정: PRD 로드맵 전면 개편 및 기능 명세서 통폐합`

2. **버전 넘버링 증가 규칙**:
   - **시작 번호**: 버전 태그 도입 초기(현재 단계)의 첫 커밋은 `[1.0.1]`부터 시작한다.
   - **PATCH (자잘한 일상 업로드/수정)**: 사용자의 요청으로 커밋 및 푸시가 발생할 때마다 패치 번호를 1씩 자동 증가시킨다 (`1.0.1` ➔ `1.0.2` ➔ `1.0.3` ...).
   - **MINOR (마일스톤 배포 완료 & 새 목표 착수)**: 1차 목표(총기, 뉴스, 레전드, 티어표)가 모두 완료되어 1차 정식 배포 판정을 내릴 때 마이너 번호를 올리고 패치는 0으로 리셋한다 (ex. `1.0.12` 완료 ➔ `1.1.0` 착수).
     *(※ 마이너 버전 변경 직전의 마지막 패치 번호가 해당 마일스톤의 '최종 완성/안정 버전'으로 인정된다)*
   - **MAJOR (대규모 도약)**: ALGS 대회 포털 도입, 실시간 TTK 시뮬레이터 구축, 시즌 2 아키텍처 전면 개편 시 메이저 번호를 올린다 (ex. `2.0.0`).

3. **사유 및 대체문구 작성 기준**:
   - **사유 명시**: 명확한 기능 구현이나 데이터 추가 시 직관적으로 기술 (ex. `[1.0.5] 레전드 28종 스킬 데이터 수집 파이프라인 구축`)
   - **대체문구 활용**: 특별한 신규 기능이 아닌 경우 다음 3가지 표준 대체문구 중 하나를 사용:
     - `버그수정`: 에러, 충돌, 수치 오탈자 교정
     - `코드개선`: 리팩토링, 성능 최적화, UI/CSS 개선
     - `문서수정`: PRD, 가이드 문서, 규칙 파일 수정

## 4. 🤖 에이전트 자동 판정 및 실행 프로세스 (Automated Resolution Workflow)
사용자가 "깃에 올려줘", "커밋하고 푸시해줘" 등 명시적 요청을 할 때, 사용자가 버전과 메시지를 직접 지정하지 않더라도 에이전트가 아래 흐름으로 자동 판정하여 신속하고 안전하게 수행한다:

1. **이전 버전 자동 추적**:
   - `git log -n 1 --pretty=%B`를 확인하여 직전 커밋 메시지의 버전 태그(예: `[1.0.2]`)를 읽어온다.
   - 직전 버전 태그가 없으면 `[1.0.1]`로 시작하고, 있으면 다음 패치 번호(`[1.0.3]`)를 자동으로 부여한다.
2. **변경점 분석 및 메시지 자동 산출**:
   - `git status` 및 `git diff --stat`을 분석하여 이번 작업의 핵심 성격을 파악하고, 사유 또는 표준 대체문구(`버그수정`, `코드개선`, `문서수정`)를 조합해 완전한 메시지를 작성한다.
3. **사전 보안 감사 (Rule 2) 실행**:
   - `.env`, 구글 서비스 계정 키 등 민감정보 파일 포함 여부를 확인한다.
4. **Commit & Push 실행 및 보고**:
   - 작업 완료 후 이번에 부여된 버전 태그와 커밋 메시지를 사용자에게 명확히 보고한다.

---

## 5. 🛡️ 브랜치 보호 (Branch Safety)
- `main` 브랜치에 대한 강제 푸시(`git push --force`, `git push -f`)는 어떠한 경우에도 실행하지 않는다.
- 원격 저장소와의 충돌이 발생하면 사용자에게 상황을 보고하고 안전한 해결책(rebase/merge)을 제안한다.
